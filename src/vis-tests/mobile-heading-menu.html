NOTE: This test must be loaded with ?mobile=1 on the URL.

Expected Behaviours
  • Menu starts folded, is visible, but not in way
  • The menu is bottom aligned, to be more reachable one-handed, and it performs layout in a fashion that makes sense
  • Mobile has no tab UI option (the key, not MWMD apps)
  • The menu can be opened with a tap, or closed
  • The GUI rendered should make the state clear
  • The menu should fold upwards not downwards, as bottom aligned
  • I should pay attention to titles, so it's easy to guess content
  • The fonts should be readable.
  • To assist dyslexic people, there are stripes on alternate items.
  • The menu has the same solid-arrow to cross symbol on the state.
  • The elements should have relevant aria-labels.
  • The menu should work on a variety of screen sizes.
  • Do something sensible if editing has meant that the named sections and the menus no longer match.
  • The menu shouldn't fall off screen.
  • Tapping to open the menu, then scrolling doesn't close the menu (like bigScreen would), the close button does. This is a fixed position menu, its fine.
  • Should hi-light on selection of chapter, briefly
  • Note this menu is in DOM element order, so at the end of the page. It is normally earlier in the DOM element list
  • I applied a hack to disable the standard page menu.
  • Also Note, the list header at the top of this list is one of the headers, but h5, so not lit up
